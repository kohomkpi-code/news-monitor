# KOHOM 뉴스룸 설계 문서 (텍스트판)

- 대상: KOHOM 뉴스룸 v1.0.8 · 작성 2026. 10. 26. · 주택관리공단 전략과
- 용도: Claude Design 등 디자인 도구에 화면 재설계·매뉴얼 개선의 바탕 자료로 올리는 문서. 그림 없이 화면 구성·글자·동작·규칙·색을 모두 글로 적었다.
- 화면 글자는 앱 그대로 `[버튼]`, 「입력칸·표 머리글」로 적었다. 재설계해도 매뉴얼이 가리키는 버튼 이름은 바꾸지 않는다(16장).
- 사용법은 `KOHOM뉴스룸_사용자매뉴얼_텍스트.md`에 따로 있다.

---

## 1. 목적과 사용자

### 1-1. 목적
매일 아침 임원 보고용 언론보도 메일을 만드는 일을 줄인다. 기사 모으기 → 거르기 → 점수·분류 → 추천 → 메일 본문 만들기 → 기록을 한 프로그램에서 하고, 기준(선정 규칙)은 사용자가 앱 안에서 고친다(환류).

### 1-2. 사용자(페르소나)
| 페르소나 | 하는 일 | 쓰는 탭 | 필요한 것 |
|---|---|---|---|
| 일반 직원(보고 당번) | 매일 조회 → 추천 5건 확인 → 메일 발송 | 베이직, 보고 기록 | 버튼 4개만 순서대로, 판단 근거는 숨김 |
| 언론보도 담당자 | 후보 전체 검토, AI 선별, 규칙 개선 | 프로, 선정 규칙, 설정 | 등급·점수·분류·키워드를 보며 고르기, 엑셀·규칙 파일 |

### 1-3. 원칙
- 설치 없이 exe 하나. 인터넷은 기사 조회와 업데이트 확인에만 쓴다. 사용 기록을 밖으로 보내지 않는다.
- AI를 앱이 직접 부르지 않는다. 담당자가 Claude 채팅에 복사·붙여넣기로 중계한다(API 키·비용 없음).
- 판단은 사람이 한다. 앱은 추천만 하고, 최종 선택·순서는 사용자가 정한다.

## 2. 전체 흐름(파이프라인)

```
[조회 기간] ──▶ ① 모으기 ──▶ ② 거르기 ──▶ ③ 점수·분류 ──▶ ④ 추천(★) ──▶ 표(사용자 선택·순서)
                 구글 뉴스     제외 매체      등급 A/A?/S/B   리스크 먼저       │
                 전문지 RSS    제목 검증      항목별 점수     A 최소 1건        ▼
                              제외어         자동 분류       분류별 상한    ⑤ 보고서(HTML) ──▶ 그룹웨어 메일
                              단순 행사                                        │
                              같은 사안 묶기                                    ▼
                              이미 보고                                     ⑥ 보고 완료 기록 ──▶ 다음 조회에서 제외

환류: 프로 [⤓ 결과 엑셀] → 선정 규칙 [개선 요청문 복사] → Claude → [Claude 답변 붙여넣기] → 규칙 저장 → 다음 조회
AI 선별(선택): 프로 [① AI 선별 요청문 복사] → Claude(판단 기준서) → [② 선정 결과 붙여넣기] → 분류·인사이트 부착
```

### 2-1. 조회 단계 순서(정확한 처리 순서)
1. 키워드별 검색: 구글 뉴스 RSS(정확 검색이면 따옴표 질의). A 키워드는 결과가 100건(구글 한 번 최대)에 차면 기간을 반으로 나눠 다시 묻고(최대 4번, 누락 방지), A 외는 키워드당 최대 30건. 키워드 사이마다 [■ 정지] 여부 확인.
2. 전문지 RSS: 켜 둔 전문지의 전체 기사 피드. 키워드 면제 전문지는 전부, 그 밖은 키워드가 맞는 것만.
3. 시작 시각 이전 기사 제거.
4. 제외 매체 제거.
5. 제목 검증: 제목(B는 요약 포함)에 키워드가 실제로 있는지 다시 확인해 등급을 매김. 등급이 없으면 제거(지사명만·전문지는 통과).
6. 제외어 제거(A·S 기사는 면제).
7. 단순 행사 기사 제거(A는 제거하지 않고 감점).
8. 같은 사안 묶기.
9. 이미 보고한 기사 제거.
10. 점수·분류 계산 → 추천 → 순번 부여(1부터, 이후 고정).

빠진 기사는 단계별 이유와 함께 보관해 엑셀 「빠진 기사」 시트로 내보낸다. 상태줄에는 "수집 N건 → 제외 매체 N건 제외 → … → 표시 N건 · ★추천 N건"으로 보인다.

## 4. 공통 틀

### 4-1. 창
- 제목줄: `KOHOM 뉴스룸 v1.0.8` · 최소 크기 980×640 · 바탕 연회색(BG).
- 머리띠(네이비 바탕): 왼쪽 앱 이름·버전, 가운데 탭 5개(켜진 탭은 흰 글자·SemiBold, 꺼진 탭은 회청색), 오른쪽 [업데이트 확인].
- 본문: 흰 패널(PANEL)들을 세로로 쌓음. 패널은 1px 테두리, 직각 모서리, 그림자 없음.
- 상태줄(맨 아래, 네이비 바탕): 상태 단어(준비·진행 중·조회 완료·정지 중·조회 멈춤·오류·안내 등) + 문장. 진행 중에는 앰버 진행 막대, 오류면 바탕 빨강.

### 4-2. 버튼 종류
| 종류 | 모양 | 쓰임 |
|---|---|---|
| 주(Primary / PrimaryBig) | 네이비 채움, 흰 굵은 글자 | 지금 누를 버튼 하나 |
| 보조(Secondary / SecondaryBig) | 흰 바탕, 회색 테두리, 네이비 글자 | 그 밖의 단계 버튼 |
| 작은(Small) | 보조와 같고 작게 | 표 도구·▲▼·추가 |
| 위험(Danger) | 흰 바탕, 빨간 글자 | [■ 정지], [선택한 기사 기록 취소] |
| 기간(Seg / SegOn) | 붙은 단추 묶음, 켜진 것은 연틸 바탕 | [자동] [오늘] [최근 3일] [최근 7일] |
| 글자(Link) | 테두리 없음, 네이비 글자 + › | [선정 규칙에서 고치기 ›] 등 |

꺼진 버튼은 연회색 바탕·흐린 글자. 조회 중에는 [조회]가 꺼지고 [■ 정지]가 켜진다.

### 4-3. 대화상자 틀
흰 본문(위에 안내문 1~3줄) + 아래 회색 버튼 단(오른쪽에 [주 버튼][취소]). 모달(뒤 창 잠금), Esc로 닫기.

### 4-4. 안내 띠
연틸 바탕(NOTE_BG)·테두리(NOTE_BORDER), 왼쪽 틸 사각 점. 탭 맨 위 설명과 보조 버튼을 담는다.

## 5. 베이직 탭

### 5-1. 구성(위 → 아래)
1. **단계 줄**: `① 조회` `② 추천 확인` `③ 보고서 열기` `④ 보고 완료로 기록` — 끝난 단계 ✓(틸), 지금 단계 진하게, 남은 단계 흐리게.
2. **조회 패널**: 「조회 기간」 시작 칸 ~ 끝 칸, [자동] [오늘] [최근 3일], 안내 "자동 = 직전 영업일 09:00 ~ 지금", 오른쪽 [■ 정지] [① 조회].
3. **결과 패널 머리**: "선택 N건 / 후보 M건"(N은 큰 숫자), 범례(★ 추천 · 공단(A) 주황 견본 · 직접 추가 청록 견본), [▲] [▼], [↻ 추천으로 되돌리기], [＋ 기사 링크로 추가].
4. **표**: 「선택」 「순번」 「날짜」 「매체」 「제목」.
5. **아래 단**: "선택한 N건이 표 순서대로 보고서에 들어갑니다 · 줄을 끌어 순서 변경", [③ HTML 보고서 열기 (메일용)], [④ 보고 완료로 기록].

### 5-2. 상태
| 상태 | 화면 |
|---|---|
| 조회 전 | 표 비어 있음, 상태줄 "[① 조회]를 누르면 시작합니다. 기간은 직전 영업일 09:00부터 자동입니다.", 주 버튼 = [① 조회] |
| 조회 중 | [① 조회] 꺼짐, [■ 정지] 켜짐, 상태줄 진행 막대·키워드 n/전체 |
| 완료 | ★추천이 선택된 채 맨 위, 주 버튼 = [③ HTML 보고서 열기 (메일용)] |
| 추천 0건 | 상태줄 "오늘은 ★추천 0건 (기준 30점 이상)" — 표에서 직접 고름 |
| 멈춤 | 누르면 "멈추는 중… 지금 묻고 있는 키워드 하나가 끝나면 멈춥니다." → "조회를 멈췄습니다. 기간·규칙을 고친 뒤 다시 [조회]를 누르세요." 멈춘 조회의 기사는 표에 넣지 않음 |
| 오류 | 상태줄 빨강 + 오류 창(예: 구글 429, 인증서) |
| 보고서 연 뒤 | 주 버튼 = [④ 보고 완료로 기록] |
| 기록 뒤 | 단계 모두 ✓, 표의 기록된 기사는 다음 조회에서 빠짐 |

## 6. 프로 탭

### 6-1. 구성
1. **조회 패널**: 체크 [이미 보고한 기사 제외] [같은 사안 기사 묶기] [단순 행사 기사 제외 (A는 감점)] · 「조회 기간」 + [자동] [오늘] [최근 3일] [최근 7일] · [■ 정지] [조회] · 키워드 요약 한 줄 + [선정 규칙에서 고치기 ›].
2. **도구 줄 1**: [전체 선택] [전체 해제] [★추천만] | 「키워드별」 목록 + [선택] [해제] [이것만] | 오른쪽 "선택 N건".
3. **도구 줄 2(순서)**: 「순서」 [☑ 선택 항목 맨 위로] [▲ 위로] [▼ 아래로] · 안내 "줄을 끌어 옮기거나 ▲▼ · 이 순서대로 보고서에 실립니다" · [＋ 기사 링크로 추가].
4. **표**: 「선택」 「순번」 「등급」 「점수」 「분류」 「키워드」 「날짜」 「매체」 「제목」.
5. **아래 단**: 왼쪽 [⤓ 결과 엑셀로 내려받기] · 오른쪽 [① AI 선별 요청문 복사] [② 선정 결과 붙여넣기] [③ HTML 보고서 열기] [④ 보고 완료로 기록].

### 6-2. 베이직과 다른 점
- 조회 후 후보 **전체가 선택**된 채 시작(베이직은 ★만).
- 선택은 베이직과 따로 저장. 같은 조회 결과를 두 탭이 공유.
- 「키워드」 칸은 규칙 문법을 지운 표시형(예: `임대주택 -민간임대 -수요` → `임대주택`, `A OR B` → `A·B`).
- 줄을 고르면 상태줄에 점수 근거 한 줄(예: "A 기관 +50(주택관리공단) 리스크 +20(빈집) 최근 24시간 +3 = 73". 여러 낱말 키워드는 실제로 맞은 구간을 「」로, 요약에서 맞은 말은 (요약)으로 표시).

## 8. 선정 규칙 탭
세로로 긴 화면(마우스 휠 스크롤). 각 구역은 흰 패널 + 번호 제목.

| 구역 | 내용 |
|---|---|
| 안내 띠 | 환류 순서 한 줄 + [개선 요청문 복사] [Claude 답변 붙여넣기] |
| ① 검색 키워드 | 여러 줄 칸 3개(A 기관 직접 · S 사업어 · B 환경), 그 아래 3개(A 지사명 · 단지명(S로 봄) · 제외어), 「지사명과 함께 있어야 하는 말」, 체크 3개(구글 뉴스 정확 검색 · B 키워드는 요약까지 확인 · S 사업어도 요약까지 확인), 「키워드당 최대 건수」, 칸마다 건수 표시 |
| ② 거르기 | 단순 행사어 · 제외 매체 |
| ③ 점수 | 가중치 숫자 칸 18개(이름·기본값 옆에 표기) + 단어 목록 칸(모회사·부처어, 리스크어, 리스크 조건어, 정책어, 정책 조건어, 공급·개발어, 일상 공고어, 전문지, 키워드 면제 전문지, 본사 지역지) |
| ④ 분류 | 분류 순서(6줄) · 정책·제도어 · 공공기관 공통어 |
| ⑤ 추천 (베이직 ★) | 숫자 칸 6개 |

## 11. 상호작용 규칙
- **선택 vs 줄 고르기**: 표 첫 칸(체크 그림)을 누르면 선택(보고서 포함) 켜고 끄기. 다른 칸을 누르면 줄 고르기(▲▼·끌기 대상)만. 선택된 줄은 진한 글자 SemiBold, 선택 안 된 줄은 흐린 회색(FAINT).
- **끌어 놓기**: 첫 칸 외 칸을 누른 채 6px 넘게 움직이면 끌기 시작. 놓는 자리에 줄이 들어감. 표 위·아래 끝에서는 자동 스크롤.
- **▲▼**: 고른 줄을 한 칸씩(Ctrl+↑/↓).
- **[☑ 선택 항목 맨 위로]**(프로): 선택된 줄을 현재 순서를 지키며 맨 위로.
- **머리글 정렬**: 머리글 클릭 = 그 열 정렬, 다시 클릭 = 반대. 사용자가 정한 순서는 사라짐.
- **순번**: 조회 때 1부터 고정. 정렬·이동해도 안 바뀜. AI 요청문의 번호와 같음.
- **보고서 순서**: 표에 보이는 순서 그대로. 본문 ②는 분류(또는 키워드)별로 묶되, 묶음 순서는 표에서 처음 나온 순서.
- **더블클릭**: 제목 → 원문을 브라우저로.
- **줄 바탕색**: 공단(A) 연앰버(A_BG), 직접 추가 연틸(MANUAL_BG), 고른 줄 SELECT_BG, 짝수 줄 줄무늬(STRIPE).
- **주 버튼 이동**: 베이직은 단계가 넘어갈 때마다 강조 버튼이 다음 버튼으로 옮겨감.
- **확인 창**: 보고 완료 기록·기록 취소·기본값으로·업데이트는 예/아니오를 묻는다.

### 12-3. 키워드 일치 규칙
대소문자·띄어쓰기 무시 · 띄어 쓴 말은 같은 순서로 낱말 사이 원문 20자 이내 · 한 글자 낱말은 다음 낱말과 합침 · `"따옴표"`는 문구 그대로 · `OR`는 대안 · `-말`은 그 말이 있으면 불일치. 같은 글자 구간을 함께 잡은 S 키워드는 1개로 센다(예: "공공임대주택" = 공공임대·임대주택 → 1개).
구글 질의: OR 대안은 각각 따옴표 문구로, `-`가 있는 키워드는 그대로 보낸다.

### 12-5. 자동 분류
category_order 순서대로 처음 맞는 것: 리스크(리스크 점수가 붙음) → 기관 직접(A) → 정책·제도(공고 아님 + 정책 점수 또는 cat_policy_words) → 모회사·부처(공고 아님 + parent_words) → 공공기관 공통(cat_public_words) → 업계·환경(나머지).

### 12-6. 추천(pick_best)
대상에서 빼는 것: 직접 추가(따로 항상 포함), A?, A 아닌 공고, min_score(30) 미만.
1. 리스크를 점수순으로 risk_first_max(2)건
2. A가 a_min(1)건 미만이면 A 최고점 추가
3. 나머지 점수순
제한: 같은 분류 per_category_max(2), 업계·환경 industry_max(1), 합계 best_count(5).

### 12-7. 같은 사안 묶기
제목 낱말 비교(포함 관계도 같은 말로 봄). 24시간 안, 공통 낱말 3개 이상 + 그중 흔하지 않은 말 1개 이상이면 같은 사안. 묶음의 낱말은 합쳐서 다음 비교에 씀. 3자리 이상 숫자는 낱말로 남김. 대표 기사 매체에 "외 N" 표시.

### 12-9. 규칙 버전과 업데이트
규칙 버전 RULES_VERSION = 6. 앱이 새 기본값을 가져오면, 사용자 값이 이전 기본값과 같은 키만 새 기본값으로 바꾸고(직접 고친 키는 보존), 이력에 "앱 업데이트(규칙 v6)"로 남긴다.
규칙 파일 형식: JSON, `"format": "kohom-newsroom-rules"`, 앱 버전·내보낸 시각·rules 객체. 빠진 키는 기본값으로 채움.

## 16. 재설계 시 제약
1. **tkinter/ttk 한계**: 표 칸별 글자색·배경 불가(줄 단위만), 둥근 모서리·그림자·애니메이션 어려움, 아이콘은 PNG 그림으로만. 웹 화면처럼 자유로운 배치는 구현 비용이 큼.
2. **버튼 이름 유지**: 매뉴얼·안내문이 `[① 조회]` `[③ HTML 보고서 열기 (메일용)]` `[④ 보고 완료로 기록]` `[⤓ 결과 엑셀로 내려받기]` `[① AI 선별 요청문 복사]` `[② 선정 결과 붙여넣기]` `[개선 요청문 복사]` `[Claude 답변 붙여넣기]` `[규칙 저장]` `[설정 저장]`을 가리킨다. 바꾸면 매뉴얼도 같이 고쳐야 한다.
3. **번호 체계**: 베이직 ①③④(②는 화면 확인 단계라 버튼 없음), 프로 ①~④, 선정 규칙 ①~⑤. 같은 번호가 탭마다 뜻이 다르다(재설계 때 정리 대상).
4. **최소 창 980×640**에서 모든 버튼이 보여야 한다(화면 배율 125% 노트북 기준).
5. **한 화면 주 버튼 하나**, 색은 팔레트 안에서만, 강조는 굵기·색으로.
6. **글꼴 내장**: Pretendard 외 글꼴을 쓰려면 exe에 넣을 수 있는 무료 글꼴이어야 한다.
