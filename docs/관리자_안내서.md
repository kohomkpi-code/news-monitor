# KOHOM 뉴스룸 관리자 안내서 (v1.3.0~, GitHub 없이)

- 대상: 앱을 관리하는 사람(설계자·언론보도 담당자). 직원은 이 문서를 볼 필요가 없습니다.
- 모든 것은 **부서 공용 구글 계정** 하나에 모입니다: 중계함(보고 기록 공유·업데이트), 업데이트 파일, 소스 백업.
- 계정 주소·비밀번호·중계함 암호는 이 문서와 소스에 적지 않습니다.

## 한눈에

| 무엇 | 어디 |
|---|---|
| 중계함(보고 기록 공유·업데이트 창구) | 부서 계정 script.google.com의 프로젝트 `KOHOM뉴스룸 중계함` |
| 보고 기록 | 부서 계정 구글 드라이브 `KOHOM뉴스룸_보고기록` 폴더(자동 생성, PC마다 파일 하나 — 지우지 않기) |
| 새 버전 exe | 부서 계정 구글 드라이브 `KOHOM뉴스룸_업데이트` 폴더(관리자가 올림) + `변경내용.txt` |
| 설치 묶음 | 부서 계정 구글 드라이브 `KOHOM뉴스룸_설치` 폴더(직원에게 나눠 줄 압축 파일) |
| 소스 백업 | 부서 계정 구글 드라이브 `KOHOM뉴스룸_소스` 폴더 |
| exe 만드는 곳 | 부서 Windows PC(Python 3.12 + Claude 데스크톱 앱) |

---

## A. 처음 한 번 — 중계함 만들기
1. 앱(v1.3.0)을 켜고 **[설정]** → 보고 기록 공유 → 공유 방식 **(●) 중계함 (앱만 있으면 됨)** → **[중계함 대본 복사]**.
   앱이 암호를 만들어 「중계함 암호」 칸에 넣고, 암호가 든 대본을 복사합니다.
2. 브라우저에서 **부서 공용 계정**으로 로그인 → `script.google.com` → **[+ 새 프로젝트]**.
3. 편집 칸의 글을 모두 지우고 Ctrl+V → 위쪽 '제목 없는 프로젝트'를 눌러 `KOHOM뉴스룸 중계함`으로 바꾸기 → 💾 **[프로젝트 저장]**.
4. 오른쪽 위 **[배포] → [새 배포]** → 톱니바퀴(유형 선택) → **[웹 앱]**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   → **[배포]**
5. 권한을 물으면 **[액세스 승인]** → 부서 계정 → "Google에서 확인하지 않은 앱"이 나오면 **[고급] → [KOHOM뉴스룸 중계함(으)로 이동(안전하지 않음)] → [허용]**.
6. **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) **[복사]** → **[완료]**.
7. 앱 「중계함 주소」에 붙여넣기 → **[저장하고 지금 맞추기]**. 오른쪽 위에 "● 기록 공유 09:12"처럼 청록 점이 뜨면 성공.
   부서 드라이브에 `KOHOM뉴스룸_보고기록` 폴더가 생기고 지금까지의 보고 기록이 올라갑니다.
8. **[연결 파일 만들기]** → `KOHOM뉴스룸_연결.txt` 저장. 이 파일이 있으면 직원 PC가 켜자마자 연결됩니다.

> 4번에서 '모든 사용자'가 목록에 없으면 회사 구글 관리자 설정 때문입니다. 전산 담당에 '웹 앱을 모든 사용자에게 배포' 허용을 요청하세요.

## B. 직원에게 나눠 주기(설치 묶음)
1. 새 폴더에 아래 파일을 모읍니다.
   - `NewsMonitor_v1.3.0.exe`(이번에 받은 설치 묶음 안)
   - `KOHOM뉴스룸_연결.txt`(A-8에서 만든 파일)
   - 매뉴얼 PDF(원하면)
2. 폴더째 압축 → `KOHOM뉴스룸_설치_v1.3.0.zip`. 부서 드라이브 `KOHOM뉴스룸_설치` 폴더에 올리거나 사내 메일·메신저로 보냅니다.
   - 연결 파일에 암호가 들어 있으니 함께 쓰는 직원에게만 주세요(드라이브 공유는 '제한됨' + 직원 계정 추가 권장).
3. 직원: 압축을 풀고 exe를 실행 → 끝. **이미 쓰던 직원**은 새 exe와 연결 파일을 쓰던 exe와 **같은 폴더**에 넣고 옛 exe를 지웁니다(설정·기록 유지).
   - 아직 v1.2.0을 쓰는 PC는 켤 때 마지막 GitHub 업데이트로 v1.3.0이 자동 설치될 수 있습니다. 그 PC에는 연결 파일만 exe 폴더에 넣으면 됩니다.

## C. 새 버전 내기(매번)
**준비(한 번):** 부서 Windows PC에 아래 두 가지를 설치합니다.
1. Python 3.12 — python.org → Downloads → Windows → 설치 첫 화면에서 **'Add python.exe to PATH' 체크** → Install Now.
2. Claude 데스크톱 앱(부서 공유 Claude 계정으로 로그인).
3. 소스 압축 파일(`KOHOM뉴스룸_소스_v1.3.0.zip`)을 `C:\KOHOM뉴스룸_소스`에 풉니다.

**매번:**
1. Claude 데스크톱 앱 → Claude Code → 폴더 `C:\KOHOM뉴스룸_소스` 열기.
2. 고칠 내용을 말합니다. 예: "보고서 제목 글자를 키워 줘. 새 버전으로 만들어 줘."
   Claude가 `CLAUDE.md`를 따라 고치고, 버전을 올리고, `build.bat`으로 시험과 exe 만들기까지 합니다.
3. `C:\KOHOM뉴스룸_소스\dist\NewsMonitor_v새버전.exe`를 부서 드라이브 **`KOHOM뉴스룸_업데이트`** 폴더에 끌어 놓습니다.
4. 같은 폴더의 `변경내용.txt`를 새 내용으로 바꿉니다(없으면 새로 만들기). 업데이트 안내창에 보입니다.
5. 직원 PC는 다음에 앱을 켤 때 "새 버전이 있습니다 → [예]"로 스스로 바꿉니다.
6. 소스 폴더를 압축해 `KOHOM뉴스룸_소스` 폴더에 올립니다(백업. `dist`, `build` 폴더는 빼도 됨).

## D. 중계함 대본 다시 올리기(Claude가 "중계함 대본이 바뀌었다"고 할 때만)
1. 새 버전 앱의 **[설정] → [중계함 대본 복사]**(암호는 지금 것을 그대로 씀).
2. script.google.com → `KOHOM뉴스룸 중계함` → 편집 칸 모두 지우고 Ctrl+V → 💾 저장.
3. **[배포] → [배포 관리] → ✏️(연필) → 버전 '새 버전' → [배포]**. ※ [새 배포]를 누르면 주소가 바뀝니다. 그러면 연결 파일을 다시 만들어 모든 PC에 다시 나눠야 합니다.
4. 순서: 대본을 먼저 올리고, 그다음 새 exe를 업데이트 폴더에 올립니다.

## E. 암호 바꾸기(연결 파일이 밖으로 샜을 때)
1. 앱 [설정] → 「중계함 암호」 칸을 비우고 **[중계함 대본 복사]**(새 암호가 만들어짐) → D-2~3대로 다시 올리기.
2. **[설정 저장]** → **[연결 파일 만들기]** → 새 연결 파일을 모든 직원에게 다시 나눠 주기(exe 옆 파일을 바꾸면 켤 때 저절로 새 암호로 바뀜).

## F. 문제 해결

| 증상 | 조치 |
|---|---|
| 오른쪽 위 "기록 공유 안 됨"(빨간 점) | 인터넷 확인 → [보고 기록] 탭 [↻ 새로고침]. 계속되면 상태줄 문구를 보고 아래 항목 확인 |
| "중계함 답이 이상합니다 … '모든 사용자'" | script.google.com → [배포 관리]에서 액세스 권한이 '모든 사용자'인지, 주소가 맞는지 확인 |
| "중계함 암호가 맞지 않습니다" | 그 PC의 exe 폴더에 최신 연결 파일을 넣고 앱 다시 켜기 |
| "중계함 대본이 이 앱과 맞지 않습니다" | D 순서로 대본 다시 올리기 |
| 업데이트가 안 뜸 | 업데이트 폴더의 파일 이름이 정확히 `NewsMonitor_v1.3.1.exe` 형식인지, 버전 숫자가 지금보다 큰지 확인 |
| "내려받은 파일이 … 다릅니다" | 드라이브에 올리는 중이었을 수 있음 → 몇 분 뒤 [업데이트 확인] |
| build.bat 실패 | 창의 오류 내용을 Claude에게 보여 주기 |

## 확인 필요 사항
- 부서 계정이 회사 도메인(Google Workspace) 계정이면 '모든 사용자' 배포 허용 여부 **미확인**.
- 중계함으로 19MB exe를 받는 데 걸리는 시간은 1분 안팎 **(추정)** — 구글 응답 속도에 따라 다름.
- 중계함·업데이트는 시험 환경(구글 드라이브만 가짜)에서 확인했습니다. 실제 부서 계정으로 처음 한 번 위 A·C 순서를 따라 확인이 필요합니다.
