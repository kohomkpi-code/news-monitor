## 2026-10-14 (1일차) — 설계와 v0.1.0 제작

### ① 개념 노트

**API (Application Programming Interface)**
사람이 쓰는 '화면' 대신 프로그램이 쓰는 '창구'. 네이버 뉴스 검색 화면을 사람이 보는 대신, 프로그램이 "이 키워드로 최신 100건 줘"라고 요청하면 정리된 데이터로 돌려준다. 창구를 쓰려면 신분증(Client ID/Secret)이 필요하고, 하루 이용 횟수에 한도가 있다. 공단 업무로 치면 '민원 창구' 대신 '기관 간 전산연계'에 해당한다.

**JSON**
API 가 돌려주는 데이터 형식. 중괄호와 따옴표로 된 '항목명: 값' 묶음이다. 사람이 읽을 수 있고 프로그램도 바로 쓸 수 있어서 거의 모든 API 가 이걸 쓴다. 앱 설정 파일(config.json)도 같은 형식이다.

**크롤링 vs API**
크롤링은 사람이 보는 화면을 긁어 오는 것. 네이버가 화면 구조를 바꾸면 바로 깨지고 약관 문제도 있다. API 는 공식 창구라 안정적이고 합법적이다. 선택지가 있으면 항상 API.

**exe 패키징 (PyInstaller)**
Python 프로그램은 원래 Python 이 설치된 PC 에서만 돈다. PyInstaller 가 Python 본체 + 내 코드 + 필요한 부품을 exe 하나로 묶어 주면, Python 없는 PC 에서도 더블클릭으로 실행된다.

**GitHub Actions**
"파일이 올라오면 이 작업을 자동으로 해라"를 적어 두는 GitHub 의 자동화 기능. 우리는 "exe 만들어서 Release 에 올려라"를 적어 뒀다. 작업은 GitHub 가 빌려주는 윈도우 가상 PC 에서 돌아가므로 내 PC 에 아무것도 설치할 필요가 없다. 공개 저장소는 무료.

**Release / 태그 / 버전 번호**
Release 는 '배포본 보관함'. 각 배포본에 v0.1.0 같은 꼬리표(태그)가 붙는다. 번호는 `주.부.수정` 세 자리: 큰 변화면 앞자리, 기능 추가면 가운데, 자잘한 수정이면 끝자리를 올린다. 앱은 실행할 때 이 보관함을 들여다보고 자기 번호보다 높은 게 있으면 업데이트한다.

**화면과 로직의 분리**
`app.py`(화면)와 나머지 파일(일하는 모듈)을 나눠 뒀다. 나중에 화면 없이 매일 아침 자동 실행하는 버전을 만들 때 모듈은 그대로 쓰고 화면만 빼면 된다. 처음부터 이렇게 나눠 두는 것이 개발자들의 기본 습관.

### ① 개념 노트

**RSS (Really Simple Syndication)**
웹사이트가 "새 글 목록"을 정해진 양식(XML)으로 내놓는 공개 게시판. 기사 하나가 `<item>` 한 칸이고, 그 안에 제목·링크·날짜·매체명이 들어 있다. API 처럼 프로그램이 읽기 좋은 형태지만 신분증(키)이 필요 없다는 점이 다르다. 대신 주는 양이 정해져 있고(구글은 약 100건), 세밀한 조건은 걸 수 없다. 공단 업무로 치면 '전산연계(API)'가 아니라 '홈페이지 공지 게시판 구독'에 가깝다.

## 2026-10-15 (3일차) — 하루 5건 추리기 (v0.3.0)

> 기사는 잘 나오는데 너무 많다 → 목표는 2급 이상 임원께 하루 5건. 별도 채팅에서 '판단 기준서(프로젝트 지침)'와 작업 지시서를 만들어 와서 반영했다. 표 정렬·키워드별 선택은 써 보며 나온 요청.

### ① 개념 노트

**프롬프트와 컨텍스트**
AI 에게 "우리 기관에 중요한 기사를 골라 줘"라고만 하면 AI 는 공단을 모른다. 그렇다고 AI 를 '학습'시키는 게 아니다. 매번 대화 앞에 **판단 기준서(기관 프로필·관심 등급·선별 규칙·출력 형식)를 쥐여 주는 것**이다. 이 기준서를 claude.ai 프로젝트 '지침'에 넣어 두면 채팅할 때마다 자동으로 함께 읽힌다. 신입 직원에게 업무 매뉴얼을 주고 일을 맡기는 것과 같다. 매뉴얼이 좋아지면 결과가 좋아지므로, 기준서는 계속 고쳐 쓰는 '자산'이다.

**클립보드**
복사(Ctrl+C)한 내용이 잠깐 머무는 윈도우의 임시 보관함. 앱의 '① AI 선별 요청문 복사' 버튼은 사람이 드래그하는 대신 프로그램이 직접 보관함에 글을 넣어 준다. 그래서 바로 채팅창에 Ctrl+V 하면 된다.

**파싱(parsing)**
정해진 모양의 글을 프로그램이 읽을 수 있게 쪼개는 것. Claude 에게 답 끝에 `12|리스크|한 줄 인사이트` 처럼 '|'로 나눈 줄을 쓰게 약속해 두었기 때문에, 앱이 그 줄을 번호·분류·인사이트로 정확히 나눠 읽을 수 있다. 사람이 읽는 답(■ 오늘의 선정)과 기계가 읽는 답(#선정 아래)을 따로 받는 것이 요령.
